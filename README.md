# Система обмена сменами дежурств

## Назначение приложения
Приложение предназначено для автоматизации процесса обмена дежурными сменами между сотрудниками. Процесс включает двухуровневое согласование: сначала обмен одобряется вторым участником (коллегой), после чего требует финального утверждения от старшего смены (менеджера).

## Стек технологий

**Frontend:**
* TypeScript
* React
* Vite
* Ant Design

**Backend:**
* Python
* FastAPI
* PostgreSQL (psycopg)
* SQLAlchemy (ORM)
* Pydantic & Pydantic Settings
* Аутентификация: JWT (PyJWT), хеширование паролей Argon2 (pwdlib)

## Структура frontend
* `src/app/` — Инициализация приложения, роутер, глобальные стили, провайдеры.
* `src/pages/` — Основные экраны приложения.
* `src/features/` — Пользовательские действия и формы.
* `src/entities/` — Типы и бизнес-сущности.
* `src/shared/` — Переиспользуемые UI-компоненты и утилиты.

## Структура backend
* `app/routers/` — Эндпоинты API.
* `app/services/` — Бизнес-логика.
* `app/schemas/` — Pydantic схемы для валидации.
* `app/models/` — SQLAlchemy модели базы данных.
* `app/core/` — Базовые настройки, конфигурация, безопасность.

## Основные пользовательские сценарии
1. **Просмотр графика**: Сотрудник просматривает расписание и видит свои/чужие смены.
2. **Взаимодействие с коллегами**: Сотрудник может получать запросы на обмен от других коллег, соглашаться на них или отклонять.
3. **Утверждение менеджером**: Менеджер имеет доступ к специальной панели, где видит список уже согласованных между сотрудниками заявок, и может вынести итоговое решение (Утвердить / Отклонить).
4. **Отслеживание статусов**: Любой сотрудник может просмотреть историю и итоговые статусы своих замен в системе. Менеджер видит историю и итоговые статусы всех замен в системе.
5. **Создание смены менеджером**: Менеджер может создавать смену для любого сотрудника.

## Основные экраны приложения
* `/schedule` — **График дежурств**. Компактный календарь с навигацией по неделям и списком смен на выбранный день.
* `/requests` — **Мои запросы**. Таблица входящих и исходящих заявок рядового сотрудника.
* `/manager` — **Подтверждение старшим**. Панель менеджера для финального утверждения заявок на обмен.
* `/history` — **История замен**. Архив всех завершенных (одобренных или отклоненных) обменов.
* `/create-shift` — **Создать смену**. Создание смены менеджером.

## Запуск проекта

Проект полностью контейнеризирован. Для локального развертывания используется Docker Compose.

1. Склонируйте репозиторий и перейдите в корневую директорию проекта.
2. Скопируйте файлы с примерами переменных окружения (например, `.env.example` в `.env`) и заполните их актуальными данными (настройки базы данных, секретные ключи).
3. Выполните команду для сборки и фонового запуска всех сервисов:
   ```bash
   docker-compose up --build -d
   ```
4. После успешного запуска приложение и API будут доступны:
   * **Frontend:** http://localhost:5173
   * **Backend API:** http://localhost:8000
   * **Swagger UI (Документация API):** http://localhost:8000/docs

Для остановки приложения выполните:
```bash
docker-compose down
```
